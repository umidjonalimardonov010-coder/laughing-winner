# Server rules (bot)
- Bot auto-replies come from `public.auto_replies` (admin page "Avto-javoblar"), cached 30 s and cleared on save.
- Conversation steps live in `public.bot_state` (taken atomically with `takeState` before money moves); saved card/bookmaker IDs in `public.user_accounts`; input rules (UZCARD/HUMO, ID, code, amount) are pure in `src/lib/exchange-rules.ts` — so the flow survives restarts and the rules stay tested.
- Bot reply keyboards: main menu and per-step keyboards (saved value + «<<< Ortga qaytish»; the old «↪️ Bekor qilish» label still works); any menu button clears the current step. With HamyonAPI the deposit follows the KARVON PAY screens the owner sent: bookmaker pick (always shown, even with one) → ID → cashdesk name → amount → `dep_method` step with «✅BARCHA ILOVALARDAN» (`dep:hp`) → receipt (`paySummary`) + payment text; the customer's card is not asked.
- Telegram alerts from server code run via `inBackground()` so the bot replies first.
- Panel «Xabar yuborish» (`broadcast.server.ts`, pure rules in `src/lib/broadcast-rules.ts`): admin text is repaired into valid Telegram HTML before sending; everyone-sends run as a `public.broadcasts` job with a runner+heartbeat lease and a user-id cursor, resumed by `resumeBroadcasts()` from the panel and the bot — so a deploy mid-send neither stops it nor sends twice.
- Mandatory subscription (`subscription.server.ts`, pure rules in `src/lib/subscription-rules.ts`): channels come from the `required_channels` setting, saved only after the bot is confirmed admin of each; the bot gates every non-admin customer step with `subscriptionGate` (after language), skips channels it can't check and caches a pass for 2 minutes — so a setup mistake never locks customers out and Telegram isn't asked on every message. Public channels never auto-link as the selfie channel.
- VIP + weekly contest (`vip.server.ts`, `contest.server.ts`; pure rules in `src/lib/vip-rules.ts`, `src/lib/contest-rules.ts`; panel page `/admin/vip`): both count only approved bot deposits (`bk_deposit`, `source = 'bot'`) and pay into the bonus balance. Cashback is claimed in `public.cashback_paid` per deposit (hooked in `approveRequest`); a week's draw claims its `public.contest_draws` row and pays inside the same transaction; only weeks ending after `contest_since` are drawn — so nothing is ever paid twice or for a week before the contest was switched on.
- Bonus → LINEBET withdraw interval (`bonus_withdraw_hours`, pure rule `bonusWithdrawWaitMs`) is re-checked inside `createBonusWithdraw` under the user's row lock and ignores refused requests — so a double tap can't pass it and a refusal never blocks the customer. Dashboard reset is a `stats_since` setting (`statsStart`), never a delete — so request history stays.
